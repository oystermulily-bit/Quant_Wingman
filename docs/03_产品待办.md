## 门禁通过后才允许，且必须按序

### A. 时态数据合同（完整版）

第一期只需成分股、日线和可交易状态。完整产品需要独立表或等价结构：

- `security_master`
- `universe_membership`
- `industry_membership`
- `daily_bars`（含 `adjustment_type, available_at, data_version`）
- `corporate_actions`
- `trading_status`
- `industry_context_universe`
- `user_whitelist`（含白名单版本、数据版本、策略版本）

必须区分事件发生时间、信息生效时间、系统真正知道的时间、数据文件生成时间。

### B. 市场与行业简单规则

仅在 1/3/5 日周期门禁通过后，才允许加：

- 少量可解释市场特征（市场收益、宽度、波动、回撤）
- 少量可解释行业特征（相对收益、宽度、波动、离散度；行业聚合必须 Leave-One-Out）
- 市场状态只调总仓/现金，或只做交互项，禁止重复计量

消融仍须与第一期同一数据、日期、标签、成本、相位、白名单、Walk-Forward 折。

无边际贡献则 `REJECT_COMPLEXITY`，退回简单方案。

### C. 公式研究闭环

仅在周期门禁通过后实现 FormulaValidationScorer。

位置：StackVM → FormulaValidationScorer → SOTA → 等权集成。

要求：硬门槛先于排序分；逐步前向接纳；不用 Holdout 选公式；不把本轮百分位分跨轮比较；失败公式只把 Development 结果写入 Knowledge Forest。

搜索预算必须预先冻结：每轮候选数、累计上限、轮数、长度、深度、算子、超时、LLM 模型、提示词版本。

公式身份必须包含规范化表达式、词表版本、特征实现版本、数据指纹、标签协议、成本协议、Walk-Forward 协议。

固定 LightGBM 只作边际因子评价器：固定参数与种子，`feature_fraction=1`，`bagging_fraction=1`，只比较 OOF，无边际贡献不得入库。

等权集成通过后，才允许研究复杂权重。

不恢复 REINFORCE。不向 LLM 发送原始行情或 Holdout。

### D. 决策与组合优化

仅在简单规则和简单集成通过后实现 PortfolioDecisionScorer。

输入职责：

1. 个股 Alpha（公式集成）
2. 市场层：总风险预算、总仓位上限、现金下限
3. 行业层：行业预算与约束
4. 优化器：在约束下生成权重，不得再次加入市场或行业分数

约束：白名单外为 0；A 股默认仅做多；单股上限；行业上限；总权重不超过风险预算；允许现金；流动性；当前持仓；相关性。

优化器不可行时的确定性回退必须预先写死，并返回 `reason_codes`。

### E. 用户建议 API

研究接口和建议接口必须分开。原始公式值只进研究接口。

用户建议响应至少包含：

`schema_version, as_of, generated_at, execution_window, horizon, unit, model_version, strategy_version, data_version, universe_version, industry_version, whitelist_id, status, reason_codes`

状态枚举至少包括：

`OK, NO_TRADE, INSUFFICIENT_EVIDENCE, STALE_DATA, UNTRADABLE, TARGET_VALID_BUT_EXECUTION_BLOCKED, MISSING_WHITELIST, MISSING_HOLDINGS, MODEL_NOT_VALIDATED, INTERNAL_ERROR`

没有当前持仓：只输出目标权重，不输出增持/减持/卖出。
没有账户资金：不输出股数，只输出比例。
没有白名单：拒绝建议。

t 日建议与 t+1 执行检查分离。执行阻塞不得回写为“当时没有信号”。

### F. 网页

仅在建议 API 合同冻结后，展示“下一调仓日组合建议”。

需要：数据截至时间、生成时间、股票池版本、白名单、主周期、确认周期、执行窗口、市场风险预算、现金下限、策略状态、全池/行业内排名、目标权重、预计换手、数据新鲜度、状态码、原因码。

不得显示未经校准的“必涨、必跌、必须买入”。
不得把 `tanh(公式值)` 直接显示为账户仓位。

### G. 一次性 Holdout

新 Holdout 不得复用任何已查看过的单票测试尾段。

运行前冻结代码、配置、数据指纹、公式集合、成本、白名单。原则上只运行一次。建立访问日志。查看后不得回调参数。失败必须如实报告，不得换指标重解释。

### H. 前向影子运行

人工白名单的主要可信结论应来自前向影子运行，而不是一次性 Holdout。

每次记录当时真实可用数据、`available_at`、白名单版本、当时建议、次日是否可执行、模拟成交与滑点、后续 3 日 / 5 日结果。记录一旦生成不得事后覆盖。不得用今天的白名单回填历史并宣传为无偏结果。
