# 产品待办

本文是第一期周期可行性研究通过之后才允许启动的后续研究与产品化清单。

`docs/02_第一期实验协议.md` 未给出以下任一状态前：

- `HORIZON_FEASIBLE_3D`
- `HORIZON_FEASIBLE_5D`
- `HORIZON_FEASIBLE_BOTH`

不得实现完整评分器、组合优化器、正式用户建议 API、建议网页、自动交易或前向影子盘产品化。现有训练 / 回测网页可以保留为研究工具，但不得改造成“下一调仓日组合建议”产品。

周期可行性只说明值得继续研究，不代表市场层、行业层、RD-Agent 公式、组合优化、正式 Holdout 或人工白名单已经有效。

数据源继续使用用户指定的行情 MCP，不使用 MT5。MCP 只负责上游采集；所有正式研究必须从不可变、本地版本化快照离线运行。

## 总门禁与顺序

后续必须遵循：

```text
A. 完整时态数据合同
→ B. 市场与行业简单规则门禁
→ C. 公式研究闭环门禁
→ D. 决策与组合闭环
→ E. 消融、选择与模型冻结
→ F. 一次性 Holdout
→ G. 正式用户建议 API
→ H. 建议网页
→ I. 前向影子运行
```

复杂模块未产生边际增量时，返回 `REJECT_COMPLEXITY`，冻结到最近一个已经通过的简单版本；这不阻止经过验证的简单版本继续下一阶段，但不得保留失败的复杂层。

正式建议 API 和建议网页不得排在一次性 Holdout 之前。提前存在的 API 骨架只能返回研究状态或 `MODEL_NOT_VALIDATED`，不能输出具有确定性交易含义的建议。

当前（2026-09-01）：执行账本重冻后，阶段4仍为 `KEEP_1D_BASELINE`（现行产物 `experiments/stage4_hs300_v2_execution_ledger`）。已实现拒绝骨架 `GET /api/v2/system-status`、`GET /api/v2/data-status`、`GET /api/v2/research/experiments/{id}`、`POST /api/v2/portfolio/recommendation`（空 `positions`，`cash_weight=1.0`）。不得把该骨架扩展为可交易权重，也不得因此启动公式研究、阶段5或 Holdout。

## A. 完整时态数据合同

完整产品需要独立表或等价结构：

- `security_master`
- `universe_membership`
- `industry_membership`
- `daily_bars`（含 `adjustment_type, available_at, data_version`）
- `execution_bars` / `execution_status`（曾入选成分的成交账本，与当日成员面板分离）
- `corporate_actions`
- `trading_status`
- `membership_spell_audit`（已实现退出日；不得写回每日成员行）
- `industry_context_universe`
- `user_whitelist`（含白名单版本、数据版本、策略版本）

必须区分：

- 事件发生时间；
- 信息生效时间；
- 系统真正知道的时间；
- MCP 拉取时间；
- 原始响应快照时间；
- 标准化数据生成时间。

正式数据链路：

```text
MCP
→ 原始响应只读快照
→ Schema / 时态 / 完整性校验
→ 版本化 Parquet 或数据库
→ manifest + 文件 SHA256 + 整体数据指纹
→ 离线研究与回测
```

已用于正式实验的快照不得覆盖。MCP 数据发生修订时创建新版本，不得静默替换旧版本。

退市、停牌、涨跌停、无法入场和延迟退出必须作为独立事件保存，不能通过删除样本改善组合结果。

## B. 市场与行业简单规则门禁

仅对第一期通过的周期增加少量可解释特征：

- 市场：收益、宽度、波动、回撤；
- 行业：相对收益、宽度、波动、离散度；
- 行业聚合必须使用点时分类并执行 Leave-One-Out。

职责固定：

- 市场状态控制总风险预算、总仓上限和现金下限；
- 行业状态控制行业预算和行业集中约束；
- 个股信号决定行业内部优先级。

市场与行业状态不得同时进入个股 Alpha、决策总分和优化器而被重复计量。第一版只能选择一种实现：

1. 市场 / 行业只控制预算；或
2. 只与个股残差信号形成预注册交互。

消融必须与第一期使用完全相同的数据快照、日期、标签、成本、调仓相位、参考组合和 Walk-Forward 折。

无稳定边际贡献则 `REJECT_COMPLEXITY`，退回第一期通过的简单周期方案。不得为了保留三层架构而修改主指标或 Holdout。

## C. 公式研究闭环门禁

只有周期可行性通过后才实现 FormulaValidationScorer。

位置：

```text
StackVM
→ FormulaValidationScorer
→ SOTA 逐步前向接纳
→ 等权公式集成
```

要求：

- 硬门槛先于排序分；
- 每接纳一个候选后立即更新 SOTA 并重评剩余候选；
- 不用 Holdout 选公式；
- 不把本轮百分位分跨轮比较；
- 失败公式只把 Development 结果写入 Knowledge Forest；
- 公式必须证明对当前 SOTA 有 OOF 边际贡献；
- 市场或单一行业 Beta 不得冒充个股 Alpha。

搜索预算必须预先冻结：每轮候选数、累计候选上限、研发轮数、长度 / 深度 / 算子上限、单公式 / 单轮超时、LLM 模型和提示词版本。

公式身份必须包含规范化表达式、词表版本、特征实现版本、数据指纹、标签协议、成本协议、Walk-Forward 协议、LightGBM 参数版本和搜索提示词版本。

必须记录累计选择机会，并增加等价公式去重、输出相关性、多重检验、Deflated Sharpe 或等价诊断，以及 PBO 或等价过拟合诊断。

固定 LightGBM 只作边际因子评价器：固定参数与种子，`feature_fraction=1`，`bagging_fraction=1`，baseline 与 challenge 使用同一有限值样本，只比较 OOF，无边际贡献不得入库。

等权集成通过后，才允许研究复杂权重。不恢复 REINFORCE，不向 LLM 发送原始行情或 Holdout。

## D. 决策与组合闭环

仅在简单规则和简单公式集成各自完成门禁后实现 PortfolioDecisionScorer。

输入职责：

1. 个股 Alpha：由公式集成输出预期 Alpha、全池 / 行业内排名和 OOF 置信度。
2. 市场层：输出总风险预算、总仓位上限和现金下限。
3. 行业层：输出行业预算和行业约束。
4. 优化器：在上述 Alpha、预算和约束下生成权重，不得再次加入市场或行业分数。

约束：白名单外为 0；A 股默认仅做多；单股上限；行业上限；总权重不超过市场风险预算；允许 100% 现金；流动性；当前持仓；股票相关性；真实换手成本。

优化器不可行时必须执行预注册的确定性回退：

1. 放宽非关键软约束；
2. 降低总风险预算；
3. 移除最低置信度股票；
4. 保留原仓位；
5. 部分或全部现金；
6. 返回明确 `reason_codes`。

t 日建议与 t+1 执行检查严格分离。t+1 停牌、涨跌停或无法成交时返回 `TARGET_VALID_BUT_EXECUTION_BLOCKED`，不得回写为“t 日没有信号”。延迟退出和退市损益不得从组合净值中删除。

## E. 消融、选择与模型冻结

至少比较：

1. 第一期简单信号；
2. 简单信号＋市场风险开关；
3. 简单信号＋行业预算；
4. RD-Agent 等权公式集成；
5. 公式集成＋简单分层规则；
6. 公式集成＋完整决策层；
7. Top-K 等权组合；
8. 简单风险倒数权重；
9. 完整优化器。

复杂版本只有在同口径 Development OOF 上产生稳定、可解释且经济上有意义的增量才能保留。失败的复杂层必须移除，不能仅因已经开发完成而进入最终模型。

通过后冻结：Git 提交、配置和随机种子、数据快照和指纹、股票池与行业版本、标签 / 成本 / 切分协议、公式集合与集成方式、市场 / 行业规则、组合构造与约束、一次性 Holdout 运行计划和参考研究组合。

人工用户白名单不用于正式历史 Holdout 主结论。正式 Holdout 验证冻结的点时研究参考组合；人工白名单的可信结果留给前向影子运行。

## F. 一次性 Holdout

新 Holdout 不得复用任何已查看过的单票测试尾段，也不得在第一期周期门禁中提前读取。

运行前冻结代码、配置、数据快照、公式集合、成本、参考组合和全部门禁阈值。原则上只运行一次，建立访问日志：

- `release_id`；
- 访问者 / 进程；
- 访问时间；
- 代码、配置和模型哈希；
- 数据与 SOTA 指纹；
- Holdout 起止日期；
- 结果路径和状态。

查看后不得回调参数。失败必须如实报告，不得更换指标、白名单或子区间重新解释。

Holdout 通过后，模型才允许进入正式建议 API 和网页产品化。Holdout 未通过时返回 `MODEL_NOT_VALIDATED`；软件仍可作为研究工具正常运行。

## G. 正式用户建议 API

研究接口和建议接口必须分开。原始公式值只进入研究接口。

用户建议响应至少包含：

`schema_version, as_of, generated_at, execution_window, horizon, unit, model_version, strategy_version, data_version, universe_version, industry_version, whitelist_id, status, reason_codes`

状态枚举至少包括：

`OK, NO_TRADE, INSUFFICIENT_EVIDENCE, STALE_DATA, UNTRADABLE, TARGET_VALID_BUT_EXECUTION_BLOCKED, MISSING_WHITELIST, MISSING_HOLDINGS, MODEL_NOT_VALIDATED, INTERNAL_ERROR`

- 没有当前持仓：只输出目标权重，不输出增持 / 减持 / 卖出。
- 没有账户资金：不输出股数，只输出比例。
- 没有白名单：拒绝用户建议。
- 数据过期：返回 `STALE_DATA`，不得复用旧建议冒充当前建议。
- t 日建议与 t+1 执行检查分离；执行阻塞不得回写为“当时没有信号”。

## H. 建议网页

仅在一次性 Holdout 通过且建议 API 合同冻结后，展示“下一调仓日组合建议”。

需要展示数据截至 / 生成时间，股票池 / 行业 / 模型 / 白名单版本，主周期、确认周期、执行窗口，市场风险预算、现金下限，策略状态和原因码，全池 / 行业内排名，当前 / 目标权重，预计换手与成本，数据新鲜度和下一复核时间。

不得显示未经校准的“必涨、必跌、必须买入”，不得把 `tanh(公式值)` 直接显示为账户仓位。

## I. 前向影子运行

人工白名单的主要可信结论来自前向影子运行，而不是历史回填或一次性 Holdout。

每次记录：当时真实可用数据和 `available_at`，数据 / 模型 / 白名单版本，当时建议和目标权重，当前持仓，次日是否可执行，执行阻塞原因，模拟成交与滑点，延迟退出和退市处置，后续 3 日 / 5 日结果以及不交易原因。

记录一旦生成不得事后覆盖。不得用今天的白名单回填历史并宣传为无偏结果。
