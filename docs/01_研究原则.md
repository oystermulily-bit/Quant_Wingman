# 研究原则

本文是 quant_w1ngman 转为沪深300研究后的宪法。任何实验、代码和产品功能都不得违反。

第一期怎么做，见 `docs/02_第一期实验协议.md`。完整评分器、优化器、一次性 Holdout、网页、API 和影子盘，见 `docs/03_产品待办.md`。门禁未通过前，不得把产品待办提前开工；正式建议 API 和网页必须排在模型冻结与一次性 Holdout 之后。

---

## 一、最高原则

1. 不得在同口径样本外验证完成前声称 3 日或 5 日优于 1 日策略。
2. 不得为了得到预期结论修改 Holdout、成本、评分权重、调仓相位或回测口径。
3. 研究不达标不等于软件故障，应返回合法状态：`MODEL_NOT_VALIDATED`。
4. 复杂方案不优于简单基线时，必须保留简单方案并停止增加复杂度。
5. 正式 Holdout 不得用于公式筛选、参数优化、权重调整、LLM 反馈或方案选择。
6. 不得将当前成分股、未来行业分类、未来停牌或涨跌停状态回填到历史。
7. 不得把公式值直接解释为账户仓位。
8. 不恢复 REINFORCE 公式生成。
9. 不向 LLM 发送原始行情、未来收益、Holdout 数据或 Holdout 结果。
10. 所有研究结论必须可以由固定代码、配置、数据指纹和随机种子复现。

补充：

11. 历史单票测试（包括但不限于 `000001.SZ` / `000001.SH`、`601899.SH`）只是早期通路试验，不得当作沪深300的 1 日基线，也不得写入正式比较。
12. 研究数据源是用户指定的行情 MCP，不是 MT5。MT5 不得作为沪深300研究、验证或回测的数据入口。
13. 软件能跑，不表示模型有效。研究未通过，只应报告 `MODEL_NOT_VALIDATED`，不得写成系统故障。
14. MCP 只是上游数据来源。每次正式实验必须先把原始响应固化为不可变、本地版本化快照；训练、验证和回测只能读取该快照，禁止在实验运行中重新拉取会变化的数据。
15. 当前人工白名单不得承担历史主结论。用户白名单的可信效果必须主要来自冻结后的前向影子运行；历史周期研究使用点时全池参考组合或预注册的确定性伪白名单。
16. 退市、停牌、涨跌停、无法入场和无法按期退出等事件不得通过删除组合事件来美化结果。信号、执行阻塞、延迟退出和最终损益必须分别记录。
17. 一次性 Holdout 必须在完整模型、成本、公式、约束和参考组合冻结后运行，并且先于正式建议 API 与网页产品化。

## 二、项目定位

quant_w1ngman 的研究目标是：

> 以沪深300点时成分股作为基础分析池，由用户自主选择候选股票；系统根据完整日线、符号因子公式、市场状态、行业状态、个股相对表现和组合风险，为用户白名单内的股票提供未来 3 日 / 5 日目标权重建议。

明确：

1. 不是沪深300指数增强。
2. 不要求贴近沪深300权重或控制跟踪误差。
3. 沪深300用于：提供基础股票池；训练和验证共享公式；提供全池横截面排名；构建市场状态；提供风险和相关性参照。
4. 行业数据用于构建行业环境，不表示自动配置整个行业。
5. 用户决定可投资白名单。
6. 白名单外股票目标权重必须为 0。
7. 系统允许持有现金和输出“不交易”。
8. 当前只使用日线数据。
9. 信号在 t 日完整收盘数据可用后生成。
10. 计划在 t+1 交易日开盘执行。
11. 不提供盘中实时喊单、精确价格预测或未经验证的涨跌阈值。

## 三、目标架构

最终目标架构为：

点时正确的数据
→ 市场、行业、个股相对特征
→ RD-Agent 候选符号公式
→ StackVM 本地执行
→ FormulaValidationScorer
→ SOTA 保留与公式集成
→ 个股预期 Alpha 和置信度
→ 市场总风险预算
→ 行业风险预算
→ 用户白名单
→ 组合优化
→ 下一调仓日目标权重

这是终局图，不是第一期施工顺序。第一期只允许验证 1 日 / 3 日 / 5 日假设所必需的最小闭环。

三层职责必须严格分开：

### 1. 市场层

只负责：市场状态；组合总风险预算；总仓位上限；现金比例范围。

市场分数默认不得直接重复加进每只股票 Alpha。

### 2. 行业层

只负责：行业状态；行业风险预算；行业集中度约束；行业内有效性评价。

行业分数默认不得同时抬高行业中全部股票 Alpha，又在优化器中重复增加行业预算。

### 3. 个股层

负责：个股相对行业的残差 Alpha；全池排名；行业内排名；3 日 / 5 日预期收益和置信度；白名单内部优先级。

默认架构不是：

```text
S = beta_market × M + beta_industry × I + beta_stock × A
```

线性总分只能作为基线消融实验，不能未经验证成为默认方案。

同一天对所有股票完全相同的纯市场变量，默认不作为截面公式的独立输入。若需交互，只允许经过明确验证的结构，例如：

```text
stock_residual_signal × market_regime
stock_residual_signal × industry_regime
```

市场和行业状态不得同时在个股公式、决策总分和优化器中被重复计算。第一版简单规则也必须二选一：要么只调总仓/现金，要么只做交互项，不能两个都做。

## 四、建议生成与执行检查分离

t 日建议生成只能使用 t 日已知信息，不得使用 t+1 实际状态回头修改 t 日信号。

1. 建议生成：根据 t 日可用数据输出目标权重。
2. 执行前检查：在 t+1 开盘根据当时真实可用信息检查停牌、涨跌停、开盘缺失、流动性、价格异常、订单约束。

如果目标有效但无法执行，返回 `TARGET_VALID_BUT_EXECUTION_BLOCKED`，不得改写为历史上“模型没有产生信号”。

---

## 五、研究结论必须可复现

每条正式结论必须绑定：

- 代码版本（Git 提交哈希；仓库尚未初始化时，先初始化再开始正式实验）
- 配置哈希
- MCP 数据源标识、接口版本、拉取时间
- 不可变原始快照路径、快照清单和数据指纹
- 股票池版本、行业版本（若已使用）
- 标签协议、成本协议、Walk-Forward 协议
- 随机种子
- 白名单版本

没有上述绑定的数字，不得写成研究结论。

## 六、明确不做

- 秒级或分钟级预测
- 盘中实时喊单
- 未验证的涨跌阈值
- 精确未来股价
- 自动连接券商下单
- 沪深300指数增强
- 用 MT5 作为沪深300研究数据源
- 在正式实验中直接重新调用 MCP，而不读取冻结快照
- 把 `000001` 等单票测试结果当作正式 1 日基线
- Holdout 反复调参
- 在一次性 Holdout 前开发具有确定性交易含义的建议 API 或网页
- 当前成分股无偏历史回填
- 用今天人工选择的白名单向历史回填并作为主结论
- 用未来涨跌停或停牌过滤历史信号
- 通过删除退市、无法成交或延迟退出事件改善组合结果
- 将行业共同收益冒充个股 Alpha
- 将市场、行业风险重复计入多层
- 将公式值直接映射为账户仓位
- 恢复 REINFORCE 公式生成
- 向 LLM 发送原始行情或 Holdout 信息

---

## 七、最终报告必须区分

1. 软件功能是否正常
2. 研究假设是否通过
3. 模型是否允许生成建议
4. Holdout 是否已使用
5. 是否仍需前向影子验证

不得因为软件运行正常，就声称模型有效。
不得因为研究未通过，就把正常的 `MODEL_NOT_VALIDATED` 状态描述为软件失败。
