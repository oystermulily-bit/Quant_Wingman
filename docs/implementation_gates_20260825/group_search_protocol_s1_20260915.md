## 1. 研究问题与边界

拟议假设：`H4_5D_GROUP_COMPLEMENTARITY_STEPWISE_V1`。

在固定的点时沪深300交易池、5日标签、交易成本与执行约束下，有限特征集合中的互补组合，能否比简单基线提供可重复的样本外增量？

- 不再要求三个原慢信号先全部成功；它们保留为诊断与对照。
- 不要求每个单因子单独击败完整基线，也不要求每个股票/行业/年份都有效。
- 不按历史赢家名单删除交易股票，不重新挑最有利的历史区间。
- 单因子低IC不自动删除；也不能因“可能存在交互”而免除最终验证。
- 首版仅研究冻结清单内已实现、已审核的特征组合，不同时生成新公式、搜索窗口或调参。
- 新增科技公司仍仅作残差参考；八项候选特征不因“已经入库”自动获得搜索资格。
- `development_adaptive=true`：既往结果已经被反复观察，新划分不能消除研究者选择偏差。

## 2. 数量建议：最终最多5个，每次最多加入2个

**建议冻结 `max_group_size=5`，不是固定必须选5个；允许0—5个。** 0表示没有找到可接纳的研究组合，不输出新策略。已有初始组合的所有实际因子列也计入5个；一对因子占2个位置，不能包装成一个“因子组”规避上限。

“因子组”在这里指一个联合评价的特征子集，不是动量/波动等目录分类；分类目录的数量无需硬限。

为什么建议5而非3、10或更多：

1. 3个是旧假设的人为数量，继续固定为3会限制探索几种互补信息。5提供适度余地，但不强制每个经济类别各占一席。
2. 目前证据主要来自有限历史期和少量时间折。股票日很多，并不代表拥有同样多的独立样本；有行业相关、日期共同冲击、5日标签重叠，以及已发生的自适应研究。
3. 5个以内，最多5次单因子删除即可做完一次完整回删检查，方便解释每一项究竟是否仍有贡献。
4. 对65个候选，单纯前向选5项最多比较65+64+63+62+61=315次；选10项则是605次，还未计算回删和成对搜索。5与本版有限预算更相称。
5. 这只是首版工程与研究风险的折中，**不是文献证明的最优数量，也不保证5个不会过拟合**。公式长度、模型容量和累计尝试同样重要。本轮不能看结果后改为8或10；扩容需新协议并累计先前尝试。

一次成组加入最多2个；允许至多12对预注册的互补候选。在查看本轮验证收益前记录配对理由，例如“动量在低波条件下是否有不同作用”。不穷举所有两两/三三组合。联合加入两个模型输入并不保证模型学到有意义的交互。

## 3. 候选清单与清理

1. 冻结最多65个实际参与搜索的候选ID、实现版本、方向、数据指纹、可用时间合同及经济分类。
2. 每个外层训练范围单独建立清理规则；首版代码只用该范围中**最早内层训练窗**识别全缺失、常数和输出完全相同的候选。不得使用后面的内层验证/外层测试收益清理候选。
3. 完全相同的训练输出按规范ID字典序保留代表，记录其他ID的排除理由。训练期相同不保证未来相同，应披露这一限制。
4. 高相关只作为冗余诊断，不凭一个临时相关阈值自动删除；单因子IC也不是这里的过滤器。
5. 被排除的候选及理由必须存档，不得在预算耗尽后换一批候选继续试而不计数。
6. 所有特征均须先通过点时数据、成员/行业生效时间、输入可用时间、未来函数等基础审核。本次选择模块消费已审计的数值面板，不代替上游构建器。

## 4. 严格区分搜索数据与评价数据

外层按日期向前推进，拟保留5个外层评价折；每个外层训练范围内设置至少3个向前推进的内层验证折。所有股票在同一天必须属于同一数据角色。实际日期及指纹仍须冻结，不能以“推荐5折”替代可执行的分割清单。

- **内层**：训练固定模型、选择因子组、回删、有限配对。这里的OOF已用于选择，不是最终独立成绩。
- **外层**：每折先独立执行完整内层流程，再固定该折选出的组合，在此前未进入该折选择过程的后续日期评价。禁止把外层收益送回搜索、选择配对或调阈值。
- 不把在全部Development上选好的同一组因子再到原折打分冒充外层验证。
- 外层评价的是“搜索流程”，各折可以选择不同组合；披露选择频率和组合大小，不根据外层最优折挑部署组合。
- 流程通过后，按原算法在批准的Development范围重做一次选择/拟合，冻结最终候选。其选择成绩不能再次作为独立验证。
- Purge沿用20个交易日；Embargo沿用5个交易日；逐日期断言训练标签结束时间早于验证信号生成时间。所有输入及标签终点必须早于本次内层可访问范围的结束时间。
- 最终Holdout继续隔离，只有既定独立评估批准后才能读取；不能用于组数、公式或停止规则选择。

## 5. 本版固定的内层评价口径

采用固定LightGBM作为**因子子集预测评价器**，不是上线决策模型。参数沿用 `ResearchConfig` 的固定默认值并纳入上下文指纹：60轮、15叶、学习率0.04、最小叶样本40、随机种子20260812、单线程、全部特征和样本比例均为1。不做早停调参，不为单个候选更改模型。

每个子集在各训练窗拟合，预测对应内层验证窗，计算每日截面RankIC，再在每折内平均；主搜索分数为各折均值的等权平均。空组使用训练标签均值预测，作为搜索零起点，不是经济门禁对照A。也支持调用方传入预先指定的初始组合，但不能看完结果后切换两种起点选最好。

**默认从空组开始。** 外部经济对照仍是A、低波单因子及旧三信号组合，而不是“常数预测”。

比较样本：先对清理后冻结清单建立固定共同有限值支持（成员、标签、各候选均有效），所有子集在同一训练/验证样本上评价，避免通过新增因子改变缺失样本获得伪增量。

- 覆盖率分母始终是内层验证日期的全部原始成员日；不删除缺失成员日提高比例。
- 共同支持覆盖率必须≥85%；每天至少10只有效股票且收益标签非退化，否则停止，不能静默跳过日期。
- 该支持是评价样本，不是新交易池；它可能比单个信号覆盖率更低。若65项共同支持不足，先返回数据可行性问题，不能让程序根据收益偷偷缩清单。
- 每日、行业及全池覆盖的完整披露由正式数据接入报告承担；搜索返回总体覆盖率与样本指纹，不能把它称为完整覆盖审计。
- “输入缺失”和“得分为0”不得混淆。模型和搜索不填0、不用未来值补齐；被排除于统计比较的样本仍在覆盖分母。

## 6. 分步搜索算法（已实现）

1. 清理清单、检查基础支持，评价冻结起点。
2. 前向：对每个未入组候选计算当前组+该候选的内层结果。
3. 加入门槛：平均RankIC增量≥0.001，且至少60%的内层折增量严格为正；通过后选择固定分数最高者。同分优先因子更少，再按规范ID排序。
4. 接纳一个后，旧的边际排序失效；对更新后的组合重新评价后续候选。
5. 回删：每次形成新组合后，逐项尝试删除（初始组合也先检查）。允许相对“已接纳最佳分数”平均下降不超过0.0005，且至少60%的折损失不超过0.0005时删除。容忍度相对于高水位，不能多次删除累计损失绕过约束。
6. 若单项加入无可靠增量且还有两个名额，才测试预注册的候选对；整对通过同样的联合增量要求才加入。两个成员不必各自先通过单因子门槛。
7. 接纳候选对后同样回删，再重评剩余候选。
8. 已接纳过的组合不再成为状态，防止加了又删、删了又加形成循环。对同一上下文同一子集的模型结果可缓存，但每次比较机会仍计预算。
9. 达到5个时先完成回删检查再停止；无可靠单项/配对增量时停止；预算不足以完成本轮全体候选比较时整轮不启动，不挑恰好先跑完的前缀赢家。

0.001与0.0005是首版待确认的内层实用阈值，不是统计显著性门槛，也不能替代经济增量要求。不得用本次真实收益选择这两个阈值。回删不能证明被删因子永久无效；贪心/有限配对也不能保证全局最优。

## 7. 预算与审计

每个内层搜索作用域建议：

- 最多65个候选、12个预注册候选对、最终最多5个因子。
- 前向比较最多320次；回删最多64次；成对比较最多96次；总计不超过480次。
- 每个提议比较（含缓存命中、失败和被拒绝）计一次，配对不能伪装成单因子跳过配对预算。
- 初始组评价单独记录；模型子集评价调用数至多比较数+1，每次评价至少覆盖所有已冻结内层折。记录调用数，不能把480理解为480次单模型拟合。
- 5个外层搜索+最终Development重选最多6个作用域，即最多2880次内层比较（含分作用域明细），不把每折预算重置后只报告480。外层评价、对照回测和历史搜索机会另外披露。
- 改模型、标签、方向、清单、配对、窗口、种子、重启或重试属于新的选择机会；外层运行器须累计跨进程预算，现有搜索对象的预算仅限单次调用，不能声称其本身提供跨进程防重置。
- 记录输入/代码/模型/划分/共同样本指纹，全部提议及失败原因、接受与删除轨迹、停止原因和最终大小。
- 本模块不使用LLM，不产生旧D20的“30轮×16公式”任务；两套预算名称不同，旧D20不被覆盖。

正式候选接受还需报告全部比较机会、多重检验与选择偏差、DSR或等价诊断、PBO或等价诊断。自适应比较不能仅给每次局部检验做Holm就宣称全流程误报率已受控；外层流程验证和最终独立评估不可省。

## 8. 最终组合验证与SOTA责任

本节以下为S1原提案；S2运行时以新计划第5—6节为准：输出方式必须明确选择，不能只证明LightGBM预测有效却自动部署等权，也不能未经确认换成预测交易。组合风险接受合同尚未完整冻结，S1的内层正常返回不是新流程GO。

内层正常结果状态为 `INNER_SELECTION_ONLY`，不能直接写为已验证SOTA。评价失败则标记 `INNER_SELECTION_INCOMPLETE` 并保留错误；后端缺失不能解释成“所有候选都没有增量”。

组合验证应在共同的真实执行口径下对比：实验A（5日旧简单信号+普通Top20）、旧三信号缓冲方案、残差低波单因子同缓冲方案；最后两个为诊断对照，不得看结果临时更换主要对照A。

先验证冻结方向、固定归一化、缺一不可平均的等权因子组合。LightGBM预测改善不等于等权交易改善；如果需要将LightGBM预测本身用于推荐，那是新的决策模型假设，不能偷偷替换。

- 主要经济要求不降：净Sharpe>0、扣费年化>0；相对A的净Sharpe≥+0.15、年化≥+2个百分点；配对块Bootstrap下限>0和既定多重检验要求；折、年份、相位、成本敏感性继续检验。
- 最终覆盖率仍按全部原始OOF成员日计算≥85%，每日/行业覆盖披露；缺失规则与持仓执行规则不变。
- 不沿用“至少两个单因子各自击败旧集成”的硬门槛，改为联合增量、回删与外层稳定性证据。这是提案，不追认v3通过。
- 保留信号代理头部、真实净收益头部、行业/年份依赖及匹配随机删除诊断，不要求所有股票均匀贡献收益。
- **最终头部集中风险的接受边界尚未冻结。** 不能直接沿用“代理头部删后IC翻号即否决”又称协议已改，也不能只披露不判断。正式运行前必须确定使用什么风险指标、阈值和对照，不能在看到新冠军后决定。
- 正式SOTA接纳必须记录具体因子组、评价协议、数据版本、外层证据与风险判定。组内成员联合有用不代表每一个都是可单独部署的“已验证因子”。

## 9. 工程交付与调用

下列交付及末尾测试数是S1初始工程记录。2026-09-15同日续建的S2独立外层预测运行器、配置准入和持久预算见新计划第8节；因此本节“尚不包含外层运行器”等描述只反映S1交付时点。真实数据/交易适配、集中风险及正式SOTA仍未因外层预测工程而自动完成。

本次新增，不修改旧研究循环与现有SOTA数据库：

- `factor_research/group_search.py`：`GroupSearchConfig`、`StepwiseGroupSearch`、联合子集评价结果和完整搜索轨迹。
- `factor_research/group_evaluator.py`：训练期清理、固定共同支持、向前时间切分、Purge/Embargo、固定LightGBM子集评价。
- `tests/unit/test_factor_group_search.py`：合成数据测试，无真实Holdout访问。

代码调用方式（`inner_*` 必须由审核过的数据适配器提供，而不是全量研究数据）：

```python
from factor_research.group_evaluator import (
    FixedLightGBMGroupEvaluator, clean_training_candidates,
)
from factor_research.group_search import GroupSearchConfig, StepwiseGroupSearch

clean, exclusions = clean_training_candidates(inner_features, earliest_train_mask)
# 冻结规则：清理后缺任一成员的预注册候选对跳过并记账，不另找替代对。
retained_pairs = tuple(p for p in frozen_pair_seeds if set(p) <= set(clean))
excluded_pairs = tuple(p for p in frozen_pair_seeds if not set(p) <= set(clean))
evaluator = FixedLightGBMGroupEvaluator(
    clean, inner_labels, original_member_mask, inner_folds,
    signal_at=inner_signal_times, label_end_at=inner_label_end_times,
    selection_end_at=outer_test_start, holdout_start=sealed_holdout_start,
    data_fingerprint=frozen_data_hash, data_role="development_inner",
)
result = StepwiseGroupSearch(GroupSearchConfig()).run(
    list(clean), evaluator, initial=(), pair_seeds=retained_pairs,
    data_role="development_inner",
)
audit_payload = result.to_dict()  # 由独立运行器存档，不直接写SOTA。
audit_payload.update(exclusions=exclusions, excluded_pairs=excluded_pairs)
```

结果中的 `holdout_read=false` 表示模块不拥有Holdout读取功能，不是操作系统级隔离证明。调用方仍必须遵守数据权限与时间合同；自定义评价回调不能靠一个字符串角色字段证明其没有读取外部数据。

本次尚不包含：真实数据库到内层数据的自动接入、外层嵌套运行器、跨进程预算账本、真实Top20交易验证适配器、完整集中风险判定、自动SOTA接纳。**分步搜索算法与预测评价器已经可调用，不代表整个新研究协议已经端到端上线。**
