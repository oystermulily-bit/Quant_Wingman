# D21-v3输入可用时间合同与修复

本次是落实用户确认的因果约束，不调整85%覆盖门槛、长窗口、收缩公式或交易池。旧源、旧覆盖率与失败证据不覆盖。范围是v3参考残差构建器及公共行业区间连接函数，不宣称所有旧单票/训练入口均已迁移。

## 信号时刻

正式日频信号固定为交易日21:00 Asia/Shanghai；统一转换UTC比较完整时刻，等于截止时刻可用，晚1纳秒也不可用。不把timestamp归一成日期来判定已知。

构建器允许测试/调用方显式传入带时区`signal_at`，同一截面必须共享同一时刻且属于该信号日。正式冻结研究保持21点，不能靠推迟signal_at让晚到数据通过。

## 每项输入的时间

- `quote_available_at`：当日有效收盘报价可得时刻。
- `preclose_available_at`：用于计算当日收益的前收盘价/除权参考价可得时刻，不是前一天的日期。若该价格依赖公司行动处理，应包含该处理所需信息的最晚可得时刻。
- `previous_quote_available_at`：计算收益或判定前一交易日报价有效性所依赖的历史报价可得时刻。
- `status_available_at`：用于停牌/有效报价判断的当日证券状态可得时刻。
- `membership_available_at`：当日该股票所属身份所需信息的最晚可得时刻。原股票对应沪深300；新增参考股票对应中证500身份及排除沪深300所需信息。
- `industry_available_at`：用于当日行业归属及科技行业资格的历史分类可得时刻，必须同时满足历史生效区间。

收益可用时刻为前四项的最大值，任一项缺失则不可用。成员与行业分别校验。有效时间不能只取生效日：生效限制与信息可得限制应同时满足。

原生可得时间存在时保留原值及`NATIVE`来源，不得覆盖为更早的派生值。仅在原协议D05/D06允许的情况下，由独立规范化步骤明确产生`DERIVED_POLICY`：日线默认当日21点、事件不早于生效日21点，并记录推导依据。原生公告时刻未知仍是未知，不冒充已取得公告证据。没有可辩护策略则保持NaT及`MISSING`。

## 构建器执行顺序

读取并检查必需时间字段 → 比较完整时刻 → 屏蔽晚到/缺失输入 → 行业和市场LOO → 仅保留沪深300目标行 → 长窗口滚动 → 沪深300内截尾排名。

- 缺少必需时间列：直接报错，不按日期静默猜测。时间值缺失：保留NaT，相应输入不可用。无时区或非法时间戳：报错，禁止猜测UTC/北京时间。
- 报价、前收价、历史报价或状态晚到：本成员日r_1d保留NaN，不参与同行均值。附带的聚合`available_at`若存在也要满足截止约束，不能替代独立依赖字段。
- 新增科技股的成员或行业信息晚到：不参与行业LOO，也不参与市场LOO；否则连“有资格作科技参考”都使用了尚未知的信息。
- 原沪深300股票行业不可得：当日行业残差缺失；其可得收益仍可按原合同参与市场均值。若仅当前行业缺失但足够历史残差支持三个窗口，历史窗口信号可继续有效，不能把它误解成回填了当前行业。
- 原目标成员身份晚到：原成员日仍保留在审计和覆盖分母中，但当日分数不可用，不参与排名。
- 每日残差按其自身信号截止时刻锁定；后续到达的数据不能倒改该日残差或补入池前目标历史。窗口的允许缺失数量及三信号缺一不可规则不变。
- 输出保留各时间及`return_time_usable`、`membership_time_usable`、`industry_time_usable`、`reference_input_usable`掩码以便审计。

## 修复与证据

`data_pipeline/hs300/input_timing.py`执行依赖时间检查；`research_d21_v3_reference_only.py`在残差前调用。公共`_join_industry_intervals`改为known_at与完整signal_at比较，解决23点信息进入21点信号的问题。

严格CLI可用`--timed-input`读取显式规范化副本，验证除时间元数据外的数据值与原冻结源一致，再写独立`experiments/d21_v3_reference_only_timing_guard_20260914/`。这不是来源追溯认证；缺失的真实请求清单仍需补齐。默认旧补源缺时间列会拒绝构建，不会创建一个虚假的合格结果。

修复复检：`experiments/d21_v3_time_isolation_fixed_check_20260914/report.json`。两个原对抗场景均通过：23点行业不得进入21点信号；晚到参考收益不得影响当日目标残差。
